你在这站里搭好一条 Bell 态线路，点「复制 QASM」，粘进云端控制台，排队等上一阵，跑出来一串 00 和 11——中间还夹着几个 01。从浏览器到真机，中间隔着好几层。

## 三样东西，三种角色

Qiskit 是 Python 的 SDK：建线路、转译、提交、取结果，一整套。Cirq 是 Google 那一支的 Python 框架，更贴近底层门与具体设备。OpenQASM 是文本中间表示，只描述「哪个门作用在哪个比特上」，不绑定语言，也不绑定硬件。

三者不是替代关系。你可以用 Qiskit 或 Cirq 建线路，导出 QASM，再让另一个平台读进去。本站实验室的线路可以展开 OpenQASM 2.0 面板直接复制，粘到任何支持它的平台都能解析。

## 真机之前，还有一次转译

真机只支持特定门集与近邻耦合。平台会先转译：把 H、T 这些门拆成硬件原生的门，把相隔较远的双门用 SWAP 搬近——每一次 SWAP 都是三个 CNOT，都是额外的错误。所以线路深度在转译后会变长，模拟器上漂亮的分布，到真机上会变宽、变斜。

云平台的免费额度通常按任务数与采样次数算，热门机器要排队。先用模拟器或平台提供的模拟后端把逻辑跑对，再花额度上真机，是更划算的顺序。截至 2026 年公开报道的量级，免费额度仍只够教学与小规模验证。

选哪个平台？生态、文档与你能拿到的设备类型，比「谁更量子」更值得比较。
