一个物理比特每一千次操作错一次，听上去还能忍。可真正有用的算法需要多得多的操作：错误不是「偶尔出一次」，而是「迟早出一次」。规模越大，出得越早。

## 三个比特守一个比特

3 比特重复码把 α|0⟩+β|1⟩ 编成 α|000⟩+β|111⟩：两个 CNOT 把 q0 与 q1、q2 关联起来。一个 X 落在 q1 上，态变成 α|010⟩+β|101⟩。

如果逐一测量三个比特，你会得到 0 或 1 的具体值，叠加态当场坍缩，α 与 β 就没了——这条路走不通。

换一种测法：只测 Z₀Z₁ 与 Z₁Z₂ 两个联合观测量。无错时两者都是 +1；q1 翻转时两者都是 −1；q0 翻转时只有 Z₀Z₁ 是 −1。两个综合征一组合，就定位到出错的那一位，再补一个 X。整个过程从没问过「α 和 β 是多少」。

这就是 <Term id="error-correction">量子纠错</Term>的核心：把逻辑信息藏进比特之间的联合性质，测量联合性质碰不到它。

亲手注入一个 X，看两个 ZZ 读数怎么变，而逻辑态那一行怎么不动。

## 从重复码到表面码

重复码只挡 X 错误，挡不住相位（Z）错误，也挡不住两位同时出错。真正要用的是能同时处理两类错误的码，比如 <Term id="surface-code">表面码</Term>：数据比特与辅助比特交替摆在二维格点上，用近邻的辅助比特反复测稳定子。物理错误率低于 <Term id="threshold">容错阈值</Term> 时，码距 d 越大，逻辑错误率越低：

$$
p_L \sim \left(\frac{p}{p_{\mathrm{th}}}\right)^{(d+1)/2}
$$

高于阈值时，加比特只会错得更快——「生死线」就是这个意思。物理比特与<Term id="logical-qubit">逻辑比特</Term>的比值，是当下工程的核心数字。截至 2026 年公开报道的量级，一个逻辑比特仍要几十到上千个物理比特，离「用很小的开销跑长算法」还有距离。

<Conclusion>
  不纠错，规模越大错得越快。重复码用两个联合测量定位一位翻转，表面码把同一套思路扩展到两类错误。阈值之下，加比特才划算；阈值之上，加比特只是加速失败。
</Conclusion>
