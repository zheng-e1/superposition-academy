「量子比特同时是 0 和 1」，这句话听上去像它一次能干两件事。真按这个想法去设计算法，多半会撞墙。差别不在「同时」，在系数与测量。

## 一个数，一支箭头

经典比特是一个数，取 0 或 1，没有别的可能。量子比特是一个单位向量 $|\psi\rangle=\alpha|0\rangle+\beta|1\rangle$，两个系数是复数。它不是「两个值同时存在」，而是一支有方向的箭头：方向定了，两个系数就定了。

读它的方式只有一个：选一个基去测。测 z 基，得到 0 的概率是 $|\alpha|^2$，得到 1 的概率是 $|\beta|^2$；测完态就落到对应的基上，原来那支箭头没了。经典比特读一百次还是同一个数，量子比特测一次就换一个态。

基的选择还带来一个自由：同一个态，换一个基去测，概率分布就变了，态本身却一点没动。$|+\rangle$ 在 z 基下是一半一半，在 x 基下却是确定的。所谓「读出信息」，很大程度上是在问选哪个基。

## 并行性的边界

n 个比特的态有 $2^n$ 个 <Term id="amplitude">概率幅</Term>。写下来很省：50 个比特就描述了一个 $2^{50}$ 维的空间。可一次测量只吐出一个 n 位结果，你拿到的是 1 个数，不是 $2^n$ 个数。想靠重复测量把全部振幅读出来也不行，因为每次测完态都变了，重复的是新的态。

所以「量子并行」不是同时跑 $2^n$ 个输入、再把答案逐个取回来。它做的是让 $2^n$ 条路径的振幅在演化中按 <Term id="phase">相位</Term> 相加：目标结果的振幅被放大，其余相消，最后测一次就大概率拿到它。算法真正设计的是这一步，也就是测量之前的干涉。

这也是量子算法稀少的原因。不是每个问题都能把答案压进一个可测的偏置里；能压进去的，才有优势。

<Conclusion>
  经典比特是一个数，量子比特是一支单位向量：方向决定系数，系数决定概率。n 个比特确实对应 $2^n$ 个振幅，但测量只还给你一个结果。信息要先靠干涉挤进一个可测的偏置，才拿得出来。
</Conclusion>
