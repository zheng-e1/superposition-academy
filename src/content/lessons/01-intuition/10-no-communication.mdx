约定一套暗号：你那边测 Z 基代表 0，测 X 基代表 1；我这边只看自己的比特是 0 还是 1，就能读出你的消息。听起来天衣无缝——纠缠的两边不是「同步」吗？真做一次就会发现，收到的永远是抛硬币。

## 单边永远是抛硬币

<Term id="bell-state">Bell 态</Term>的一边，单独沿任何方向测，两个结果都各一半。关键在于这个「一半」不随另一边改变：你把 A 端测了、没测、早测、晚测、换基测，B 端的单边统计一动不动。

会变的是联合分布。以 $|Φ+⟩$ 为例：A 测 Z、B 也测 Z，同号率 100%；A 测 Z、B 测 X，同号率掉到一半。换成 $|Ψ+⟩$ 那一类，Z 基下同号率会是 0。可这些数字都要两张记录单并排才读得出来。

## 关联不是通信

要看出 100% 的同号，必须把两份记录放在一起逐行比对。这一步需要一条经典信道：电话、光纤、快递硬盘都行，但它们都受光速限制。整条链路的速度由最慢的一环决定，纠缠没有省掉任何时间。

<Term id="teleportation">量子隐形传态</Term>是最好的例子：它确实把态送了过去，代价是两个经典比特，还得先打电话。缺了那通电话，接收方手里只有噪声。

顺便说清「坍缩瞬间」是什么。它是条件概率的更新，不是远处发生的物理推动。A 得到 0 之后，只有把结果用经典方式送过来，你才知道「B 那一位现在可以按 |0⟩ 去预期」；消息到达之前，B 自己测出来的仍是各一半。这个「知道之后才更新」的差别，正是不可通信定理的内容：任何局部操作都改不了远处的边缘分布。

<Misconception
  note="关联是两列数据之间的关系，通信是把一列数据送到对面；前者不需要传东西，后者绕不开光速。"
>
  <Fragment slot="wrong">B 端一测就知道 A 端测了什么，所以把 A 的测量选择换成 0 或 1，就能发报。</Fragment>
  <Fragment slot="right">B 端看到 0 或 1 的概率恒为一半，与 A 测什么、测不测无关；只有拿到 A 的记录逐行比对，才能看出同号还是反号。</Fragment>
</Misconception>

<Conclusion>
  纠缠让两边的记录高度相关，可每一端的单边结果都彻底随机，而且不随另一端的设置改变。想利用关联，必须比对记录；比对要走经典信道。所以「瞬时」只是我们整理联合分布时的说法，不是信号。
</Conclusion>
